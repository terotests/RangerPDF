# PDF viewer

A PDF parser and renderer in Rust-syntax Ranger, sans-IO: the host hands it
the file's bytes and the substitute fonts, and gets back per page a display
list (fills, strokes, clips, images, text with positions), the page's text,
find boxes, bookmarks, or the page as RGBA pixels / a PNG file. It is tested
on rust, es6, kotlin, dart and swift (`SUITES=pdf web/test.sh`) and compared
with pdf.js on pdf.js' own test corpus (`PARITY.md`). No pdf.js code is used;
pdf.js is the reference for behaviour only.

The desktop app (`desktop/app/pdf_view.rs`) shows a PDF's pages in the
preview pane with it: each page is rendered at the width it is shown at and
drawn as one image.

```rust
let mut d = PdfDocument::open_with_fonts(bytes, "", fonts); // or open(bytes, password)
d.page_count(); d.page_width(0); d.page_height(0);          // points, after /Rotate
let page = d.render(0);        // PageOut: cmds, images, text, warnings
let r = pdf_raster::rasterize(&page, 2.0);                 // RGBA at 144 dpi
d.page_png(0, 1200.0);         // PNG 1200 px wide
d.text(0); d.find(0, "word"); d.outline();
```

## What it reads

- File structure: xref tables and streams, hybrid files, object streams,
  incremental updates, and repair by scanning when the xref is broken.
- Filters: Flate, LZW, ASCIIHex, ASCII85, RunLength, PNG/TIFF predictors.
  DCT (JPEG) images, baseline and progressive, are decoded by `pdf_jpeg.rs`;
  JPX, JBIG2 and CCITT images are not decoded (the raster draws them grey).
- Encryption: the standard security handler, revisions 2 to 6 (RC4, AES-128,
  AES-256), user and owner passwords.
- Fonts: TrueType, CFF / OpenType, Type 1 (pfb and pfa), Type 3, CID fonts
  with embedded CMaps, Identity-H/V, ToUnicode, encodings with Differences,
  and metrics of the standard 14 fonts. A font that is not embedded is drawn
  with a substitute face from `FontFiles`: keys `sans`, `serif`, `mono` (each
  also `-bold`, `-italic`, `-bolditalic`), `symbol`, `dingbats`. pdf.js'
  standard fonts (Liberation Sans, Foxit) fit; `desktop/build.sh` copies them
  to `bin/fonts/pdf`. Predefined CJK CMaps are not included.
- Graphics: paths, clipping, line styles and dashes, all colour spaces
  (Device, CIE-based as their alternates, ICCBased by component count,
  Indexed, Separation, DeviceN with all function types), images and masks
  (stencil, SMask, Mask, colour key), form XObjects, tiling patterns, axial
  and radial shadings. Mesh shadings (types 4 to 7) are drawn in one colour
  with a warning. Blend modes are ignored; constant alpha is kept.
- Annotations are not drawn.

## Pictures

`pdf_picture.rs` reads picture files for the desktop preview: PNG, JPEG
(`pdf_jpeg.rs`), BMP (incl. RLE and bit fields), GIF (`pdf_gif.rs`, the first
frame) and TIFF (`pdf_tiff.rs`, the first page; none, PackBits, LZW, Deflate
and JPEG compression, strips or tiles). The format is told from the bytes.
`PicImage::open_ints(bytes).png_ints(width)` gives the picture as a PNG at most
`width` pixels wide. EXIF orientation and animation are not applied, and CCITT
fax TIFFs are not read.

```rust
let p = pdf_picture::decode(&bytes); // p.ok, p.w, p.h, p.rgba
```

## Files

- `src/pdf.rs` the entry point (`PdfDocument`)
- `src/pdf_doc.rs` the file: xref, objects, repair, page tree
- `src/pdf_lexer.rs`, `src/pdf_obj.rs` tokens and objects
- `src/pdf_filters.rs`, `src/pdf_inflate.rs` stream filters
- `src/pdf_crypt.rs`, `src/pdf_hash.rs` encryption (MD5, SHA-2, RC4, AES)
- `src/pdf_render.rs` content streams to a display list (`pdf_display.rs`)
- `src/pdf_raster.rs` the display list to anti-aliased RGBA; `src/pdf_png.rs`
- `src/pdf_font.rs` fonts; `pdf_truetype.rs`, `pdf_cff.rs`, `pdf_type1.rs`
  the font programs; `pdf_cmap.rs`, `pdf_glyphs.rs`; `pdf_fontdata.rs` is
  generated by `tools/gen-fontdata.js` (the Adobe Glyph List and the standard
  14 fonts' widths, from AFM files)
- `src/pdf_color.rs`, `src/pdf_func.rs`, `src/pdf_image.rs`, `src/pdf_path.rs`
- `src/tests.rs`, `src/tests2.rs` the tests (`main.rs` runs them)
- `tools/bench.js` the parity benchmark against pdf.js

Every module's name starts with `pdf_` and struct names avoid common words,
because Ranger's names are global across the program the module is compiled
into (the desktop app also has EVG, RangerPPTX, RangerDocx and web/graphql).
